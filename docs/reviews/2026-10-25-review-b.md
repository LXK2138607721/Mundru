### P2 — 卡片双击焦点没有从 Crop 图片坐标转换到 Fit 图片坐标

- 首个错误接口：`D:\test\Lumina\app\src\main\java\com\lumina\cleaner\ui\deck\DeckCard.kt:89-90`。
- 消费方：`D:\test\Lumina\app\src\main\java\com\lumina\cleaner\ui\viewer\PhotoViewerOverlay.kt:137-139`。
- 相关显示：卡片 `DeckCard.kt:137` 为 `ContentScale.Crop`；查看器 `PhotoViewerOverlay.kt:276-277` 为全屏 `ContentScale.Fit`。
- 调用链：DeckCard 卡片局部坐标除以卡片尺寸 → CardStack:255 → MainActivity:1120-1123 / 1248 → 查看器把该比例乘以全屏 viewport → PhotoTransform.zoomedAt。
- 触发条件：图像实际显示矩形与全屏 viewport 不相同，尤其是竖屏中浏览方图/横图，或卡片发生 Crop 时。两种显示空间不能直接共用一个归一化坐标。
- 最小复现：1000×1000 原图在 1000×1000 卡片中，双击位置 x=50%、y=10%；查看器为 1000×2000，Fit 后原图上沿 y=500，因此原图被点中的像素在查看器 y=600。实际编译的 `PhotoTransform.zoomedAt(.5,.1,1000,2000)` 给出 scale=2.5、translationY=1200，使该点被变换到 y=1200，而不是在其 Fit 后位置 y=600 锚定；正确的 translationY 应为600。被点中的细节会明显偏离焦点。
- 证据：不入生产源码的 Java 探针直接调用本候选编译出的 PhotoTransform 类；`D:\test\Lumina\app\build\review-b\FocusProbe.java`、`focus-probe.txt`。
- 最小修复建议：将双击接口定义为归一化的原图像素坐标；卡片先根据 Crop 实际显示矩形反算原图坐标，查看器再根据 Fit 实际显示矩形映射到 viewport 坐标，最后调用缩放数学。保留回收站默认参数入口。补充方图/横图/超长图与 Crop 边缘的跨组件映射回归。

### 焦点链路已修正

实际检查 `PhotoTransform.kt:28-44`、`DeckCard.kt:91-92`、CardStack 转发、MainActivity 的 `viewingZoomFocus` 转发及 `PhotoViewerOverlay.kt:137-143`：

1. `imageFocusFromCrop` 用 `max(cardWidth, cardHeight × imageAspectRatio)` 得到 Crop 图片显示宽度，加入居中裁剪偏移后将卡片坐标反算为原图归一化坐标。
2. MainActivity/CardStack 原样传递原图焦点；查看器新增参数明确了坐标含义。
3. `zoomedAtImageFocus` 用 `min(viewportWidth, viewportHeight × imageAspectRatio)` 得到 Fit 真实显示宽高，再计算2.5x平移目标；不会把 Fit 留白当成图像内容。
4. 查看器自身双击仍使用 viewport 坐标的 `doubleTapTarget` 路径；回收站默认不传 initialZoomFocus，既有入口不受此坐标接口变更影响。

读取新增4项焦点回归：方图留白、横图裁剪边缘、超长图裁剪，以及6种比例×4种位置的24组像素锚定。方图样例准确断言 translationY=600 与像素仍在 y=600。

独立适配原数学探针，直接运行当前已编译的 PhotoTransform/ImageFocus 类；未修改原 `FocusProbe.java` 或 `focus-probe.txt` 失败证据。结果：
